## 1. 项目背景与目标

用户在投递简历时发现：获奖、证书、项目、实习等经历时间一长就忘了，证明文件也找不到。于是做一个**本地运行的个人素材库**：

1. 先把经历和证明文件集中存好、找得到（素材库，已完成）
2. 再用 AI 帮忙录入和整理（第二期，未开始）
3. 最终能粘贴岗位描述（JD），自动挑出相关经历、生成定制简历条目（第三期，未开始）
4. 用一张 3D “神经元”星图展示全部经历（已完成，含三轮美化）

调研结论（做项目前查过）：市面上有 brag document 类 App（BragLog、BragBook、Log My Work、brag-cli）、笔记图谱工具（Obsidian、Logseq、TheBrain）、AI 知识库（Atomic、open-recall）和 3D 简历展示（VividCV），但没有一个同时做到“结构化简历素材 + 证明文件归档 + 图谱可视化 + 按岗位召回”。这就是本项目的定位。

## 2. 关于用户（协作偏好）

- 用中文交流。偏好 **Python**，不熟或不想碰 JavaScript 构建工具链。
- 分工是“**主要由 Claude 写代码，用户能看懂即可**”：代码要清晰，**注释用中文**，密度与现有代码一致。
- 重要改动前，用户喜欢**先讨论方案、确认后再实施**（尤其是视觉、交互类改动）。给方案时附上推荐项。
- 视觉改动做完后，用户希望看到**前后对比截图**。
- 第二期（AI）用户明确说“不着急”。

## 3. 运行与开发环境

- Windows 11，Python 3.12（miniconda），项目虚拟环境在 `.venv/`。
- 用户自己用 `start.bat` 启动，端口 **8765**，使用的是**真实数据** `data/`。
- 本机有 Node.js（只在重新打包 3D 库时用到），**没有** GitHub CLI `gh`。
- 仓库：https://github.com/Juansive/Individual-MAP

### ⚠️ 测试规则（重要）

1. **绝不在 8765 端口、绝不用 `data/` 目录做测试**，那是用户的真实数据。
2. 测试时另起一个服务器，用环境变量指向测试数据目录：
   ```bash
   IMAP_DATA_DIR=<某个临时目录> .venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8767
   ```
   测试数据可以通过页面表单 POST `/entries/new` 批量造（字段见 `routes/entries.py` 的 `apply_form`）。
3. `.claude/launch.json` 里配置了一个不带测试目录的预览服务器（同样指向 `data/`），**慎用**；用户的程序在运行时它会自动换到别的端口，但仍然读写真实数据。
4. 后端 Python 改动需要重启服务器；静态文件（JS/CSS）不需要，`static_url()` 会给地址加版本号，刷新即可。
5. **自动化测试**：`.venv/Scripts/python.exe -m pytest -q`（依赖在 `requirements-dev.txt`）。`tests/conftest.py` 会把数据目录指到临时目录，并断言确实如此，所以跑测试不会碰真实数据。改了后端逻辑就跑一遍；新功能尽量补测试。
6. 需要用真实数据验证（比如数据库升级）时：用 SQLite backup API 把 `data/map.db` 复制到临时目录，用 `IMAP_DATA_DIR` 指过去测，测完删掉副本。

## 4. 架构

```
浏览器 ──HTTP──> FastAPI (app/main.py)
                  ├─ routes/*.py      处理请求，读写数据库
                  ├─ templates/*.html Jinja2 服务端渲染页面
                  ├─ static/          CSS + 少量原生 JS
                  └─ SQLModel ──> data/map.db (SQLite)
                     vault.py ──> data/vault/ (证明文件)
```

刻意选择了**服务端渲染 + 原生 JS**，不用 React 等前端框架：用户偏好 Python，也避免了 Node 构建步骤。星图页面是唯一的“重前端”页面，单独一个 `graph.js`。

### 4.1 数据模型（`app/models.py`）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `Entry` 条目 | kind, title, org, role, level, start, end, description, highlights | 一段经历或一项荣誉。`start/end` 是 `YYYY-MM` 字符串，`end="now"` 表示至今；`highlights` 一行一条 |
| `Skill` 技能 | name（唯一）, category | 和条目多对多（`EntrySkillLink`）。category 取 `SKILL_CATEGORIES` 的 key（tech/tool/language/soft，空串 = 未分类），决定星图颜色 |
| `Attachment` 证明文件 | entry_id（可空）, original_name, stored_path, sha256（唯一）, mime, size | `entry_id` 为空 = 在“待归类”里。用内容哈希去重 |
| `EntryLink` 条目关联 | from_id, to_id, relation | 有方向。relation 取 `RELATIONS` 的 key：produced（产出/来自）、during（期间/期间于）、related（相关）。同一对条目只能有一条关联（不分方向） |

条目类型 `ENTRY_KINDS`：education 教育经历 / internship 实习工作 / project 项目经历 / competition 竞赛 / award 奖项荣誉 / certificate 证书资格 / research 科研论文 / campus 校园活动 / volunteer 志愿公益 / other 其他。每种类型带颜色和完整度规则（`needs_proof` / `needs_numbers` / `needs_skills`）。

时间字段用 `pydantic.NaiveDatetime`：SQLModel 0.0.48 默认要求带时区的时间，写普通的 `datetime` 会报错。

### 4.2 关键流程

- **上传文件**：`web.save_form_files()` → `vault.save_upload()`：先算哈希去重 → 先写数据库并 flush → 再写文件（避免留下孤儿文件）。上传到条目时，如果同一文件已经在待归类里，会顺手移过来。
- **文件命名**：`vault/{年份}/{类型}/{YYYY-MM}_{标题}_{原文件名}.ext`；待归类在 `vault/_待归类/`。编辑条目保存时，`vault.organize()` 会把位置对不上的文件移过去，再用 `prune_empty_dirs()` 清掉空文件夹；“导出与备份”页的「整理全部文件」（`/vault/organize`）对所有文件做同样的事。
- **删除**：删条目时它的文件放回待归类、它的关联一并删除；删文件时移到 `data/trash/`，不会真正删除。
- **技能管理**（`routes/skills.py`）：重命名成已存在的名字（不分大小写）时直接合并；合并时用到旧技能的条目改用目标技能，不会重复添加；删除技能只去掉标签，不影响条目。
- **完整度检查**：`completeness.check_entry()` 返回缺失项列表，列表页、详情页、星图都在用。
- **备份**（`app/backup.py`）：
  - 启动时自动做数据库快照到 `data/backups/auto/`，保留最近 10 份；上次快照后数据库没变就跳过，所以频繁重启不会把旧快照挤掉。证明文件不会被程序真正删除，所以自动快照只备份数据库。
  - `/export/backup` 手动生成完整备份（数据库 + vault 打成 zip）。
  - 恢复：关掉程序，把快照复制成 `data/map.db`。
- **数据库升级**（`app/migrations.py`）：用 SQLite 的 `PRAGMA user_version` 记录执行到第几个升级。**改表结构时，除了改 models.py，还要在 `MIGRATIONS` 末尾追加升级函数**（用 `add_column` 等可重复执行的工具）。启动时 `init_db()` 先 `create_all` 再执行未执行的升级；升级前自动快照，每个升级一个显式事务，出错回滚。注意：Python sqlite3 默认不会给 ALTER TABLE 开事务，所以连接用了 `isolation_level=None` 并手动 BEGIN/COMMIT，不要改回 `with conn:`。

## 5. 星图实现要点（`app/routes/graph.py` + `app/static/graph.js`）

### 5.1 数据（`/api/graph`）

节点 id 约定：`me`、`kind:<key>`、`entry:<id>`、`skill:<id>`、`org:<机构名>`。连线 type：`tree`（我→类型→条目）、`skill`（条目→技能）、`org`（条目→机构）、`relation`（条目→条目，带 `outLabel`/`inLabel` 两端说法）。条目节点的 `size` 由“充实度”决定（描述、成果、文件、技能越多越大）；技能节点带 `category`/`categoryLabel`，颜色取自类别。

**成长等级**（`app/levels.py`，规则经用户确认）。**设计原则：大类必须比它的分支更耀眼**（用户明确提出的），所以特效按层级分配，而不是给分支封顶：
- **分支（单条经历）**：Lv1 星尘（只有标题）→ Lv2 行星（有时间和描述）→ Lv3 卫星行星（有证明文件或成果要点）→ Lv4 环带行星（完整度全部通过）→ Lv5 闪耀行星（完整，且 2 条以上带数字的成果 + 2 个以上技能，或级别为国家级/国际级）。每级要求先满足上一级。**分支只有卫星（Lv3+）和星环（Lv4+，Lv5 更亮），没有日冕。**
- **大类（类型节点）8 级**：成长值 = 下面各条经历的等级之和；进度 = 成长值 ÷（`KIND_TARGETS` 目标条数 × 5），最多 100%。门槛在 `KIND_LEVELS`：0/10/20/35/50/65/80/100%，前密后疏（用户确认：分得更细，而不是上限更高，所以每个大类都能到顶）。每类目标条数不同（教育 2、奖项 6……），因为天然条数差别很大。每升一级多一样外观：Lv1 星云（星雾）→ Lv2 原恒星（变大、内核更亮）→ Lv3 星团（伴星）→ Lv4 环带恒星（星环）→ Lv5 双环恒星（第二道星环）→ Lv6 日冕恒星（日冕）→ Lv7 旋涡星系（双臂星系盘）→ Lv8 璀璨星系（三臂星系盘 + 金色光晕 + 日冕强脉动）。节点额外带 `need`（升到下一级还差几点）。
- **核心技能**（被 4 条以上经历用到，`star=true`）：星环。

条目和大类节点都带 `growth`、`growthName`、`progress`（0~1，进度条用）、`nextSteps`（升级还差什么）；条目另有 `satellites`（Lv3 起，每个证明文件或成果要点一颗，最多 6 颗）。注意：条目节点里的 `level` 字段是“级别”（国家级等），不是成长等级。

前端连线颜色：`tree`、`skill` 用终点节点颜色，`org` 灰蓝，`relation` 淡金（`LINK_RGB`）。条目的关联经历用 `relationsOf(node)` 取，信息卡和详情面板都会列出。

### 5.2 前端结构（`graph.js` 按区块组织）

| 区块 | 内容 |
|---|---|
| 小球外观 | `orbMaterial()` 自定义着色器（Fresnel 边缘光“玻璃珠”，支持雾）；`makeNodeObject()` 组装外壳、内核、光晕、待完善光圈、文字标签（CSS2DObject） |
| 悬停信息卡 | `tooltip()` 返回 HTML，由库的 nodeLabel 显示 |
| 高亮 | `setHighlight()` 只设目标值（targetFade/targetBoost），渐变在 `animate()` 里逐帧完成 |
| 神经放电 | `fire()` 每 2~4 秒沿 我→类型→条目→技能 用 `Graph.emitParticle()` 发信号，到达的节点 `pulse=1` 闪一下 |
| 时间分层 | `orbitForce()` 自定义力：压扁成星盘 + 吸到年份轨道；`showYearRings()` 画年轮；牵引线 `tether`；弹簧回弹 `spring`/`stepSpring()` |
| 镜头 | `fitView()` 自己算距离（“我”固定在原点）；`focusNode()` 飞到节点 |
| 背景星尘 | `starLayer()`；远景 `stars.sky` 跟随镜头，近景 `stars.dust` 世界坐标漂移 |
| 入场动画 | `playIntro()` 按层级设定 `__appearAt`/`__revealed`；连线在两端都 revealed 后才显示 |
| 成长特效 | `makeNodeObject()` 末尾按层级分配，工具函数 `addAura`（星雾/光晕）、`orbiter`（卫星/伴星）、`addBelts`（星环，两种倾斜 `TILT_A/B`）；日冕 `coronas`、星系盘 `galaxyDisc(r, color, arms)` 只给大类 |
| 升级庆祝 | `findCelebrations()` 对比 localStorage 里上次的记录：`imap.graph.levels.v2`（每个节点的等级）和 `imap.graph.lit.v2`（每套等级点亮到第几级）。第一次只记录不庆祝；改了等级规则要换键名版本号。`celebrate()` 先逐个升级（大类优先，最多 3 个：飞过去 + `burst()` + `showToast()`），再播“首次点亮”（面板对应行闪烁） |
| 点亮进度面板 | `renderAchievements()` 渲染徽章和每级的达到数量（“点亮”= 有节点当前等级 ≥ 该级）；`jumpToLevel()`：一个节点直接 `selectNode`，多个先 `showGroup()` 框住，再点依次切换；`closestToUpgrade()` 给出“离升级最近”。一组高亮存在 `state.group`，鼠标移开用 `restoreHighlight()` 恢复。折叠状态存在 prefs 的 `achvCollapsed` |
| 等级提示 | `growthBlock()`：信息卡和详情面板里的等级、进度条（`progress`）、升级还差什么 |
| 逐帧动画 | `animate()`：明暗渐变、呼吸、放电闪光、入场缩放、弹簧、星尘、景深雾 |

### 5.3 可调参数速查

| 想调什么 | 位置 |
|---|---|
| 辉光强弱 | `new UnrealBloomPass(..., 强度 0.85, 半径 0.45, 阈值 0.2)` |
| 小球质感 | `orbMaterial` 片元着色器里的 `pow(..., 2.2)`（边缘光宽度）和 `color * 0.22`（中心亮度） |
| 放电频率 | `scheduleFire` 中的 `2200 + Math.random() * 2000` 毫秒；`HOP_MS` 每跳时长 |
| 回弹手感 | `SPRING_K`（刚度）、`SPRING_C` 中的 0.55（阻尼比，越小越弹） |
| 呼吸速度 | `animate()` 里的 `Math.sin(now / 1000 * 1.3)` |
| 入场节奏 | `INTRO_STEP`（每层间隔毫秒），`animate()` 里的 `/ 650`（单个弹出时长） |
| 星空亮度 | `updateStars()` 里两层的 opacity；`starLayer()` 的数量和大小 |
| 网络松紧 | `d3Force("charge").strength(-50)`、`d3Force("link").distance(...)` |
| 年轮间距 | `ringRadius()`：`45 + (年份 - 最早年份) * 32` |
| 升级门槛 | `app/levels.py`（`entry_growth`、`kind_growth`、`KIND_LEVELS` 大类门槛与名字、`KIND_TARGETS` 各大类目标条数、`STAR_SKILL_MIN`、`MAX_SATELLITES`） |
| 卫星/星环/日冕外观 | `makeNodeObject()` 的“成长特效”段：卫星轨道半径 `r * (2.1 + i * 0.35)`、星环内外径、日冕大小和亮度 |
| 星系盘外观 | `galaxyDisc()`：粒子数、半径范围 `r * (2.2 + t * 3.4)`、旋臂弯曲 `t * 3.6`、颗粒大小 `r * 0.22`；转速在 `animate()` |
| 庆祝节奏 | `celebrate()` 里的两个 `sleep`；`burst()` 的持续时间 `t / 1.5` |

### 5.4 踩过的坑（务必知道）

1. **Claude 的浏览器面板经常处于隐藏状态，此时 `requestAnimationFrame` 不运行**，动画、物理模拟、镜头补间都不推进。测试时：
   - 用 `forceGraph().tickFrame()` 手动推进物理模拟（`forceGraph()` 在 graph.js 里定义）
   - 弹簧可以手动调用 `stepSpring(1/60)` 逐帧验证
   - 截图会触发一次渲染，所以截图本身能看到当前状态
   - 连续动画的观感没法亲眼确认，需要让用户实际看
2. **不要用库自带的 `Graph.zoomToFit()`**：在上面的环境里和自动旋转、补间叠加时会把镜头卡进中心球里。用 `fitView()`。
3. **镜头飞行动画和 OrbitControls 自动旋转会互相干扰**：飞之前先 `stopRotate()`。
4. **库的 `onNodeDragEnd` 调用顺序**：库会先删掉节点的 `fx/fy/fz`，再调用我们的回调，所以在回调里重新设置 fx 是有效的（弹簧回弹靠这个）。
5. **自定义 ShaderMaterial 要支持雾**，必须合并 `UniformsLib.fog`、加上 fog 的 shader chunk，并设置 `fog: true`。
6. **浏览器缓存旧 JS**：已经通过 `web.static_url()` 加 `?v=修改时间` 解决，模板里引用静态文件**都要用 `static_url()`**。
7. 3D 库是用 esbuild 打包成 IIFE 挂在 `window` 上的（`tools/graph-lib/entry.js`）。**必须打包在一起**，否则泛光模块和 3d-force-graph 会用到两份不同的 three.js。新增 three 的扩展模块（比如 CSS2DRenderer）时，要改 entry.js 重新打包：
   ```bash
   cd tools/graph-lib && npm install && npm run build
   ```
   打包完删掉 `node_modules`。

## 7. 重要决策记录

| 决策 | 原因 |
|---|---|
| 先做素材库，3D 放在最后 | 核心痛点是“想不起来、找不到文件”，3D 是展示层 |
| 本地网页，不部署上网 | 个人敏感数据；开发最简单 |
| FastAPI + Jinja + 原生 JS，不用 React | 用户偏好 Python，避免 Node 构建 |
| 星图三层结构（我→类型→条目↔技能/机构） | 数据少时也能连成一张网 |
| 时间分层采用“轨道”方案（方案 C） | 年份是固定事实，所以轨道不动、小球回弹；讨论过“外圈跟着小球动”和“停下后再变”，都被否了 |
| 美化：玻璃珠 + 收敛辉光，放电取代常驻光点 | 用户反馈原来太亮、像霓虹灯；要更克制 |
| 文件删除一律进回收目录 | 防止误删证明文件 |
